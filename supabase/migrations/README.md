# Database migrations

Apply SQL migrations from this directory in timestamp order to the configured Supabase project. The first creates requester-owned tickets. The second adds the trusted staff allowlist, shared queue access, status updates, and verified requester email snapshots. The third adds private ticket attachments and requester/staff storage policies. The fourth adds staff assignment. The fifth adds requester/staff ticket conversations. The sixth adds a staff-only equipment and asset register. The seventh links requests to assets for staff triage. The eighth allows staff to edit asset details. The ninth adds requester and staff-set ticket priority. The tenth lets requesters reopen their own resolved or closed requests when they send a follow-up. The eleventh adds a mosque/client-site field to requests and assets. The twelfth creates a shared mosque/client directory, backfills existing names, and links tickets and assets to it. The thirteenth adds device monitoring. The fourteenth gives equipment its own category list and moves any old “account access” equipment category to “other”. The fifteenth adds an Atera-style ticket type (Incident, Problem, Request, or Change), defaulting existing tickets to Incident. The sixteenth replaces ticket categories with Hardware, Software, Printer, Network, Email, and MS365, and moves existing tickets to the closest new category. Run each file once in the Supabase SQL Editor.
